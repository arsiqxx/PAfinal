# Game of Life Simulation — Serial / OpenMP / MPI / Hybrid (C++)

Final project для курса "Parallelization of Algorithms".

## 1. Задача

**Игра жизни Конвея** — клеточный автомат на поле N×N. Каждое поколение каждая клетка смотрит на 8 соседей:

- живая клетка с **2 или 3** живыми соседями выживает;
- мёртвая клетка ровно с **3** живыми соседями оживает;
- иначе клетка мёртвая.

Края поля склеены (тор). Новое поколение вычисляется **только из старого**, поэтому все клетки одного поколения независимы — задача хорошо распараллеливается (data parallelism). Сложность: O(N² · steps).

## 4. Реализация

### Хранение поля
Одномерный `std::vector<uint8_t>` размера `(rows+2) × N`. Строки `1..rows` — данные, строки `0` и `rows+1` — **ghost-строки** (копии соседних строк). С ними подсчёт соседей одинаков для всех клеток. Столбцы "заворачиваются" через `j==0 ? n-1 : j-1`. Два буфера `cur`/`next`, после каждого шага `swap` (O(1)).

### Serial
Цикл по поколениям: заполнить ghost-строки (копия последней/первой строки) → посчитать `next` → `swap`.

### OpenMP
Тот же код + `#pragma omp parallel for schedule(static)` над циклом по строкам. Потоки читают только `cur`, каждый пишет только свои строки `next` → **нет гонок данных**, блокировки не нужны. Неявный барьер в конце `parallel for` гарантирует, что поколение готово до `swap`. Подсчёт живых клеток — `reduction(+:alive)`.

### MPI (explicit data ownership)
- Поле режется на **горизонтальные полосы**; процесс `r` владеет строками `[start, start+local_rows)` и хранит **только их** (+2 ghost-строки). Если N не делится на число процессов, первые получают на 1 строку больше.
- Каждый процесс сам генерирует свою часть: начальное значение клетки зависит только от её глобальных координат (`initial_cell(i, j)`), поэтому раздавать поле не нужно, и результат совпадает с serial.
- **Halo exchange** перед каждым поколением: два `MPI_Sendrecv` — первая строка уходит соседу сверху, последняя — соседу снизу; полученные строки ложатся в ghost-строки. Соседи замкнуты в кольцо (тор). `Sendrecv` исключает deadlock.
- Итоги: `MPI_Reduce(SUM)` — число живых, `MPI_Reduce(MAX)` — время (по самому медленному), `MPI_Gatherv` — сбор поля на rank 0 только для проверки.

### Hybrid MPI + OpenMP
Внутри каждого процесса цикл по строкам тоже распараллелен через OpenMP. Например `mpiexec -n 2` + `OMP_NUM_THREADS=4` = 8 исполнителей. Так обычно работают кластеры: MPI между узлами, OpenMP внутри узла.

### Выводы
- Максимальное ускорение ≈ **5.4×** (MPI, 16 процессов).
- **От 8 к 16 прирост маленький**: физических ядер 8, остальные 8 — SMT (hyper-threading), они делят одно ядро.
- Эффективность падает с ростом p: задача **memory-bound** (на клетку мало вычислений, много чтений памяти) — потоки упираются в пропускную способность памяти; плюс обмен ghost-строками и барьеры.
- Версия с 1 потоком медленнее serial (~0.84): компилятор хуже оптимизирует цикл внутри OpenMP-региона, плюс накладные расходы на запуск параллельной области каждое поколение.
- MPI немного быстрее OpenMP на 8–16: у каждого процесса свои маленькие массивы → лучше кэш, нет false sharing на границах.
- Weak scaling: при росте поля вместе с p время растёт умеренно (0.98 → 1.46 с до 8 исполнителей) — опять из-за общей пропускной способности памяти.

## 7. Сложности и оптимизации
- **Граничные условия** — решены ghost-строками: код подсчёта соседей не содержит `if` для краёв по вертикали.
- **Deadlock в MPI** — при паре `MPI_Send`/`MPI_Recv` все процессы могли бы одновременно ждать отправки; `MPI_Sendrecv` это исключает.
- **Одинаковое начальное поле** при любом разбиении — хеш от координат вместо `rand()`.
- **Двойная буферизация + swap** — без копирования поля каждое поколение.
- **schedule(static)** — работа на каждую строку одинакова, динамическое распределение не нужно.
- Возможные улучшения: хранить клетки битами (в 8 раз меньше памяти), неблокирующий обмен (`MPI_Isend/Irecv`) с перекрытием вычислений внутренних строк, 2D-разбиение на блоки.

## 8. Вопросы, которые могут задать на защите
- **Почему нет гонок данных в OpenMP?** Читаем только `cur`, пишем в `next`, каждый поток в свои строки.
- **Зачем ghost-строки?** Чтобы посчитать соседей крайних строк своей полосы, нужна одна строка соседнего процесса.
- **Почему время MPI = MAX по процессам?** Программа заканчивается, когда заканчивает самый медленный.
- **Strong vs weak scaling?** Strong — задача фиксирована, растёт p (время должно падать в p раз). Weak — работа на исполнителя фиксирована (время в идеале не меняется).
- **Speedup / efficiency?** S = T_serial / T_p, E = S / p.
- **Почему не 16× на 16?** 8 физических ядер, память — узкое место, коммуникации (закон Амдала).
